
- Cancelamento/devolução/troca/crédito só via RPCs fn_venda_cancelar, fn_devolucao_registrar, fn_troca_registrar, fn_credito_usar; vendas canceladas ficam com cancelada=true e saem de useVendas — por quê: estoque, caixa e auditoria atômicos no banco.
- Estoque lista/totais vêm de fn_estoque_listar/fn_estoque_resumo (useEstoqueLista, 30 por página) — por quê: não depender da carga global e respeitar acesso por unidade no banco.
- NFC-e identifies the customer only from the sale's cliente_id and a valid CPF/CNPJ stored in clientes — why: the fiscal XML must use persisted, server-validated data.
- AppProvider wraps the routed application once at the App root — why: shared menus and pages must never render outside application state during navigation or hot reload.
- Decants: ml balances live only in the append-only decant_ml_ledger and change only through fn_decant_* RPCs (row lock + idempotency key); the module is gated by configuracoes key 'decants' — why: no negative ml, full audit trail, and the module can be switched off without touching existing flows.
- Decants analytics (dashboard, perdas, rentabilidade, 360°, relatórios) come only from fn_decant_* read RPCs that strip cost/margin server-side; losses live in append-only decant_perdas fed by triggers — why: exports can never leak costs and every number reconciles with the ledgers.
- Decants reposição/alertas come only from fn_decant_reposicao/fn_decant_alertas (read-only, per-filial via fn__pode); limits live in configuracoes 'decants' — why: one server-side source for badges, dashboard and suggestions.
- Decants labels print via browser HTML sized by decant_etiqueta_modelos (thermal driver), generated and audited only by fn_decant_etiquetas_imprimir; /d/:codigo scan page uses fn_decant_scan_publico (anon, non-sensitive) or fn_decant_scan (logged, per-filial, costs by permission) — why: works with any label printer and scans never leak data.
- Testers become decant frascos only via fn_decant_tester_para_frasco (locks tester row, -1 tester, FR code, ledger opening with informed ml, origem='tester') — why: tester and ml balances stay atomic and audited.
- Olfactive profiles are AI-filled only through the perfil-olfativo-ia function, which writes only to perfumes whose four profile fields are all empty and skips low-confidence answers — why: never overwrite human-entered data or store guesses.
- Transfer Notes (NT) are created only by internal fn__nt_emitir/fn__nt_receber/fn__nt_cancelar inside the same transaction as the flow event, gated by configuracoes 'notas_transferencia'; rows are immutable by trigger, costs live in a table with no API grant and are exposed only by fn_nt_detalhe with nt.ver_valores — why: atomic, auditable, never leaks cost.
- NT emission is wired by AFTER UPDATE OF status triggers on transferencias/decant_transferencias, inside fn_transferir (manual, suppressed by the local setting lejess.nt_suprimir when a larger flow emits one NT) and inside the atomic fn_reposicao_enviar/finalizar/cancelar and fn_transferencia_manual RPCs — why: existing RPC bodies stay untouched and every NT lives or dies with its stock movement.
- NT printing (A4 per-via PDF and 72mm thermal HTML) is built from fn_nt_detalhe and logged by fn_nt_registrar_impressao; the destination copy is blind while in transit — why: every print is audited and paper never shows expected quantities to the receiver.
- NT interface (list filters/CSV, per-origin card, settings, overdue-receipt alert) reads only fn_nt_filtrar/fn_nt_por_origem/fn_nt_alertas and writes settings only via master-only fn_nt_config_salvar — why: visibility and value hiding stay enforced server-side, including CSV exports.
- Retroactive NTs are issued one at a time only by master-only fn_nt_emitir_retroativa (finished transfer/reposição, mandatory reason, no stock change, retroativa flag set via a transaction-local setting read by the column default) — why: immutability trigger stays untouched and nothing runs in batch.
